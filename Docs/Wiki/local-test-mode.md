# 单人双边测试模式

description：解释第一版由一个人操作双方、查看双方信息的测试目标，以及单窗口、玩家会话与正常隐藏信息的边界。

状态：2026-10-13 用户已选择“先供我单人测试，允许查看双方信息”；首批影响力运行实现已建立，见 [第一个Demo](first-demo.md)。用户随后询问是否需要两个客户端，当前建议为单客户端/单窗口，不把该询问视为要求联网。

## 当前建议

第一版是一个本地测试宿主、一局权威状态、美苏两个固定身份会话。界面可以同时展示双方手牌并切换要操作的一侧；不用启动两份游戏进程，也没有网络连接。面板可分栏，分栏不等于两个客户端。

查看双方信息帮助检查卡牌、选择和数值。切换操作侧不改写实际 Actor、回合、选择归属或预算；不轮到的一侧仍会得到规则拒绝。修改局面、悔棋和任意改骰不因查看双方信息而自动包含在首批范围。

## 与后续同机双人的关系

| 模式 | 玩家怎么用 | 看到什么 |
|---|---|---|
| 单人双边测试 | 一个人切换美苏操作 | 显式测试观察视图可读双方手牌 |
| 同机双人 | 两个人轮流操作同一窗口 | 当前玩家私有信息；换人时遮挡 |
| 联网双人 | 两台设备或两个客户端 | 各自玩家视图；另需传输、身份和同步 |

当前推荐第一种，以便尽早验证规则。后续同机双人沿用规则核心、身份会话和普通玩家投影，再增加换人交接显示；联网还需要独立的网络工程，不能称为一键切换。

## 接口约束

- 普通 PlayerViewSnapshot 仍按身份过滤，不能全局开启 reveal-all 来省事。
- 只由可信 LocalTest 宿主创建测试观察入口，返回同版本只读数据；不向普通客户端提供任意身份或调试权限参数。
- UI 拿不到可写 GameState；测试观察与玩家提交分开。完整牌库顺序和 RNG 不作为查看双方手牌的附带输出。
- 保存模式和测试场景标识时与规则状态分开表达；正式游戏加载门禁保持严格，不能把缺卡牌处理器的场景称为完整对局。
