# 地图表现边界与未定画风

> description: 区分规则地图、视觉布局和主题资源；说明未来2D/3D地图、拾取、卡牌外观与换画风的接入方式。
> 状态：2026-09-27设计；用户尚未选定画风，本次没有制作最终图像、场景或美术资源。
> 入口：[数据契约](map-card-contracts.md)、[布局Schema](../Contracts/layout.schema.json)、[主题Schema](../Contracts/theme.schema.json)。

## 1. 这次设计的是什么

同一个CountryId在规则中表达一个可操作的桌游国家/区域，在布局里表达位置与可点击形状，在主题中表达外观资源。三者通过ID连接；地图不需要拥有同一张底图、同一组坐标或同一种渲染方式。

| 层 | 决定什么 | 换画风时 |
|---|---|---|
| MapDefinition | 国家、地区、稳定度、战场、规则邻接 | 保持同一规则版本 |
| MapLayout | 节点锚点、标签位置基础、选取形状、连线路径 | 可换排布或视图实现 |
| ThemeDefinition | 国家外观、卡框、字体、图标等资源映射 | 更换主题资源及必要适配器 |

例：同一国家可以显示为写实地形中的区域、纸质情报地图上的色块，或简洁桌游中的节点。点击后都只得到CountryId，由Application查询/提交操作；不能因为两块美术区域接触，就自动增加一条规则邻接。

## 2. 画风方案的取舍

目前不替用户选择。下面是设计方向而非已创建素材：

- 简洁桌游地图：国家节点、明显邻接线和影响力数字，规则阅读直接，适合第一版验证交互。
- 写实情报地图：历史地图纹理、清晰区域边界和简洁信息标记，能表达冷战氛围；仍需优先保证战场、控制方和可选目标可读。
- 立体风格地图：用地形、模型与镜头强化空间感；要额外处理遮挡、镜头、拾取和性能，布局及视图工作会更多。

建议第一版交互使用自制简洁占位图，等完整规则闭环后，用同一个小地区比较候选画风，再选正式方向。这是后续制作建议，不代表本轮已经开始原型或用户已选中该风格。

## 3. 布局契约

layout_id/content_version标识一份布局；map_dataset_id只引用规则地图，不复制其属性。Flat2D的anchor是归一化二维坐标：左下为(0,0)，右上为(1,1)；视图自行转换屏幕坐标并保持纵横比，不能把像素坐标写进规则。Mesh3D使用三个分量的局部坐标，x向右、y向上、z向前；单位在该布局资源中约定，不代表现实距离。

nodes覆盖正式地图的全部国家和两个超级大国，并按node_id唯一。超级大国可以显示与查询规则连线，但普通国家操作不能把它当CountryId。pick_shape_key引用布局自己的拾取形状，可对应2D多边形/热点或3D碰撞体；必须有确定的节点映射，不能根据贴图像素颜色、译名或显示名猜ID。

connection_routes是可选的绘制覆盖：有覆盖时验证端点对应真实规则边；没有覆盖时可根据规则边和锚点画默认线。规则边集合始终来自MapDefinition，路线数据不能新增或删除邻接。自交路线是绘制问题，不会生成中间交点国家。

换成不同正式地图包时必须重新校验所有节点、连线和布局覆盖，不能仅凭字符串map_dataset_id相同就认定兼容。局部原型只加载明确的fixture包，不把缺国家的布局标成完整地图。

## 4. 主题契约与资源回退

theme_id/content_version标识主题；compatible_layout_kinds声明支持Flat2D或Mesh3D。主题可以只支持其中一种，不承诺2D图片能直接变成3D世界。

country_overrides与card_overrides按稳定ID指定资源键；未单独配置时使用默认国家外观与默认卡框。美术缺失可显示占位图并报告；布局拾取缺失、未知规则ID或不兼容视图则阻止进入该交互视图，不能悄悄选中另一个国家。正式主题资源键在外部资产目录中解析，本次示例没有真实可加载资源。

资源格式、材质管线、镜头风格、配色、历史地图投影和最终国家形状都未冻结。后续确定样式后再扩展展示契约版本；不在Core里增加Unity引用。

## 5. 视图和交互边界

拟定MapView读取MapDefinition的可公开静态信息、MapLayout、ThemeDefinition以及PlayerViewSnapshot。输入适配器把点击/触控转换为CountryId，再由会话提供合法目标与操作。Presentation只呈现合法性结果，不自行计算政变限制、费用或胜负。国家标签、影响力数字与卡牌说明必须支持本地化；仅以颜色区分阵营不足，还应提供符号或文字提示。

CardView也按CardId读公开定义和主题，但手牌内容必须来自过滤后的玩家视图。换主题、打开卡牌面板、预加载贴图或错误日志都不能泄露对手手牌和牌库顺序。

~~~mermaid
flowchart LR
    A[规则地图与卡牌定义] --> D[视图组合]
    B[布局：位置与拾取] --> D
    C[主题：外观资源] --> D
    S[玩家可见快照] --> D
    D --> E[显示与交互]
    E --> F[仅提交国家或卡牌ID与操作意图]
    F --> G[会话和规则核心]
    G --> S
~~~

验收目标是：同一命令序列与相同规则包，在两个主题下得到同一权威状态摘要；只有截图和资源成本可以不同。改变布局不改变规则邻接，跳过动画不改变结果。这些是待实现的验收要求，本次没有启动Unity验证。
