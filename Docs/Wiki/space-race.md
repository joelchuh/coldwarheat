## 当前可调用子集

先读模块JSON的entrypoints，再定位对应符号：

- `SpaceRaceDefinition` / `SpaceStepDefinition` / `SpaceAbilityDefinition`（Core/Rules/SpaceRaceDefinition.cs）：防御复制、只读；校验连续位置、骰区间、唯一ID与能力引用。
- `SpaceTrackState`：双方位置必须在同一轨道内，只有查询接口；并不证明已经完成推进或领取奖励。
- `SpaceAbilityRules.Query`：每次由双方位置推导四项能力。本人超过里程碑但对方已追到时，能力仍失效。总行动轮额度无能力为null，交给回合模块提供普通额度。
- `SpaceRaceDefinitionLoader.LoadSubset`（Infrastructure/DataLoading）：严格解析共享JSON和支持的配置形状；数值直接来自Data，输入源引用不等于可信RulePack认证。

流程：共享JSON → 严格加载 → 不可变定义 + 双方可信位置 → Query → 只读能力值 → 后续头条/回合编排按阶段使用。

上述轨道查询不会掷骰、消耗次数或卡牌、产生VP、允许弃牌或开启额外行动。普通尝试的计算部分见下一节，完整宿主流程仍是设计。测试文件为SpaceAbilityTests.cs（121项，含9×9位置组合）和SpaceRaceLoaderTests.cs（51项）；[实际报告](../Testing/space-track-foundation.validation.json)。

## 普通尝试计划（已实现）

先定位Core/Rules/SpaceAttemptState.cs与SpaceAttemptRules.cs：

- `SpaceAttemptState.Create`：绑定同一日历与轨道，从可信位置建立零次数初态；不是恢复任意旧存档的入口。
- `ValidateAttempt`：检查请求回合、非计分牌、目标存在、当前能力额度与目标OPS门槛，不读随机源。
- `PlanAttempt`：按AttemptId和完整请求事实去重，再Fork随机副本掷骰；成功只推进一格，失败也次数+1。按对方是否已到目标取共享先到/后到VP，US正、USSR负。
- `BeginNextTurn`：只推进相邻合法回合并清零次数，保留位置/收据；同回合重试返回原状态，不能再次抹掉已花次数。

流程：可信用牌授权/OPS报价（宿主待接） → 资格/请求去重 → Fork → 单次范围采样 → 不可变After/Receipt/RandomAfter/VP/牌去向意图 → 宿主原子提交（待接）。

同ID同事实返回原收据，`VpDeltaToApply=0`、`ApplyCardDisposition=false`，随机前后均为当前快照，不能倒退到原收据时点。CardDefinition必须绑定同一对象；完整恢复功能须重绑批准目录，当前尚无该恢复入口。4096条收据是工程上限。

[通用OPS报价](ops-general.md)已实现；SpaceAttemptRequest.FromQuote只从真实卡Space报价取得Actor/Card/有效OPS。底层服务仍接受可信的正整数EffectiveOps，不自行计算通用修正/地区奖励，也不验证持牌、阶段、中国牌状态或活动拦截。调用方缺这些策略时不能放行完整玩家命令。普通带星牌的太空去向意图仍为Discard且不执行牌面事件；中国牌返回ChinaTransferRequired，转交与外部钩子并未实现。

IRandomProvider必须守Capture只读/Fork独立契约；本实现拒绝相同实例、初态不一致、非法骰点及未推进快照，但不声称能防恶意共享隐藏状态的提供者。范围采用NextInt(min-1,max)+1，和普通[min,max]骰面一致；PCG拒绝采样可能消耗多次原始输出。

测试：SpaceAttemptTests.cs 25项，SpaceAttemptPlanTests.cs 71项（48组目标/骰点各覆盖双方与先后到达）；[验证报告](../Testing/space-attempt-plans.validation.json)。事件推进、跳格奖励政策、卡牌/VP实际提交、胜负证据与存档恢复仍待接入。

## 1. 模块选择与职责

采用SpaceRaceService处理普通尝试和经授权的轨道推进；SpaceAbilityRules提供只读能力查询。回合、头条与出牌模块查询能力，不各自维护一份已获得奖励。相较在TurnFlow硬写所有太空条件，这样可以独立测试；相比动态脚本执行器，显式方法能清楚区分“出牌尝试”与“事件推进”。

| 接口（标明当前实现） | 输入 → 输出 |
|---|---|
| SpaceAttemptRules.ValidateAttempt（纯资格已实现） | 权威出牌上下文、当前格、卡牌有效OPS、已用次数及规则定义 → 资格与拒绝原因 |
| SpaceRaceService.ResolveAttempt | 已验证尝试与注入随机源 → 骰子、成功/失败、轨道与奖励计划 |
| SpaceRaceService.PlanEventAdvance | 已注册效果授予的推进请求 → 无普通尝试计数的推进计划 |
| SpaceAbilityRules.Query | 双方轨道位置和能力定义 → 当前生效的能力集合 |
| SpaceAbilityRules.BuildEndTurnDecision | 审核完成的状态与合法手牌 → 可选弃一张牌的PendingDecision或无决策 |

模块不直接读JSON、写磁盘、发网络消息或等待动画。Application授权玩家，RuleEngine串行提交状态和领域事件。

## 2. 轨道数据

以下最低OPS检查目标格；骰点是原始六面骰结果，不把卡牌OPS加到骰子上。普通成功只前进一格，投入更多OPS不提高成功率。数值以space-race.json为唯一参数来源，依据R2015 §6.4与M-DELUXE官方地图。

| 目标格 | 最低有效OPS | 成功骰点 | 先到/后到VP | 先到且对手未追到时的能力 |
|---|---:|---|---|---|
| 1 人造卫星 | 2 | 1–3 | 2 / 1 | 无 |
| 2 动物进入太空 | 2 | 1–4 | 0 / 0 | 每回合至多尝试2张太空牌 |
| 3 载人太空飞行 | 2 | 1–3 | 2 / 0 | 无 |
| 4 载人地球轨道 | 2 | 1–4 | 0 / 0 | 对手先选并展示头条 |
| 5 月球轨道 | 3 | 1–3 | 3 / 1 | 无 |
| 6 登月 | 3 | 1–4 | 0 / 0 | 回合末可弃1张扣留牌 |
| 7 航天飞机 | 3 | 1–3 | 4 / 2 | 无 |
| 8 空间站 | 4 | 1–2 | 2 / 0 | 每回合可进行8个行动轮 |

中文名称是展示建议，业务使用space.*和ability.*稳定ID。基础起点是0，不是已占据第1格；终点从最后一格推导，不在各服务再写一份最大格常量。不同画风可以改变轨道布局，不改变次序和数据。

## 3. 普通尝试的命令流程

用户将通过未来PlayCardCommand选择Space用途，只提交CardId；目标固定为当前格的下一格，玩家不能自行传奖励、骰点、次数或跳格。

~~~text
身份/版本/出牌资格
→ 卡牌用途、目标存在、有效OPS、当前尝试额度
→ 在事务草稿中登记用牌与AttemptId，尝试计数+1
→ 权威随机源掷骰一次
→ 失败：位置不变；成功：前进一格并计算奖励
→ 提交牌区/次数/轨道/VP批次/能力变化
→ 胜负检查；未终局才继续根行动
~~~

失败仍消耗这张牌和本回合尝试次数。非法尝试不消费任何状态或随机数。计分牌没有可用OPS，不能送入太空；有效OPS由现有预算服务按当前玩家和已生效修正计算。地区专用奖励没有太空地区目标，不能自动拿来提高OPS门槛资格。

正常太空用牌不执行这张牌的事件，不因星号移出游戏，普通实体牌进入弃牌堆。已有持续效果的“卡被打出”钩子仍按各自规则检查，不能把“不触发此牌事件”理解为跳过所有外部效果。

中国牌按F2010第4页对应问答允许用于太空，仍使用独立ChinaState与转交策略，不进入弃牌堆；也不能给它亚洲专用OPS奖励。其不可妨碍计分牌、不可被强迫使用等资格继续生效。US使用中国牌导致相关持续效果取消的钩子不被太空用途吞掉；具体效果由卡牌策略处理。

到达终点后不得再用牌尝试，即便仍有剩余次数。事件只给“若干OPS”也不能拿来作太空尝试，因为缺少可按Space用途打出的实体牌；允许实际打出另一张牌的事件需单独验证该用途授权。依据R2015 §6.4.1–6、§7.4.2及F2010 §6.4问答。

## 4. 奖励和能力的生命周期

SpaceState保存双方Position、AttemptsUsedThisTurn、计数所属TurnNumber、AppliedAdvanceIds与必要的到达记录。奖励记录包含AdvanceId、来源步骤、格子、到达顺序、是否发放VP以及VP批次ID。先到与后到由权威结算顺序和对手已到位置判断；不能按双方同时点击按钮就发两个先到奖。

在基础单向轨道下，能力是否有效可直接推导：本方已达到该格，对手尚未达到。无需另存四个可能过期的可写布尔值；能力变化事件只服务显示和审计，计算仍以位置为准。

- 第2格：本回合第一次普通尝试若刚好到达第2格，可在后续自己的行动轮使用第二次机会。若对手在第二次出牌前追到该格，额度立即恢复普通值；已完成尝试不回滚，也不会获得“负次数”。
- 第4格：在建立新的头条选择组时查询能力，对手先锁定并公开，然后拥有者选择；事件排序仍按头条原规则。头条已经选好后才获得能力，不重开本轮选择或撤回公开信息。
- 第6格：在回合末HeldScoringAudit之后查询，允许拒绝或从合法普通手牌选择一张；不是弃掉全部剩余牌，也不是随机抽弃。选择后不触发被弃牌事件；中国牌不在候选集合。若此前已经终局，不再产生决策。
- 第8格：提供本回合8个行动轮的总额度，不写成“普通额度+1”。早期普通额度为6时，规则字面上提供至多两个额外名额；后期通常一个。额度只由数据决定。新增名额在标准行动轮完成后按原先后顺序提供，不能刚到达就插队立即再出牌。

第8格是可选权益；拥有者可选择不使用剩余额外名额。调度器分别记录CompletedSlots、已明确放弃本回合太空额外名额的标志以及其他来源的授权，不能把放弃太空权益变成通用跳过正常行动。每个新名额开启前重查资格；对手追到第8格后取消尚未开始的太空额外名额，不撤销已经合法开始或完成的根行动。

尝试次数在TurnStart、头条前归零一次；获得能力不是额外重置。无手牌的正常资格与事件限制交给ActionEligibility，不由太空模块猜测跳过。回合末弃牌和额外行动不能补救已经触发的扣留计分牌失败。

## 5. 事件直接推进独立处理

PlanEventAdvance只接受已注册卡牌策略生成的授权：Beneficiary、SourceEffectId、步数/路径、VP发放政策、上限处理及原帧引用。它不是玩家可调用的任意MoveSpace命令。

事件推进不花普通太空尝试次数，也不自动掷骰；使用事件路径正常处理卡牌事件和去向。普通尝试、事件推进必须共享同一轨道变更与奖励入口，防止两个模块分别给一次VP。多格推进逐步记录到达，哪些格给VP由已核实卡牌政策决定；不能所有事件都发中间格奖励。

若已核实的卡牌政策只给目标格VP，也不能因此关闭途经能力的查询；具体卡牌的前置条件、超过终点和逐步胜利时点必须在该卡策略中明确。没有完整授权政策则在状态修改前报错，本次不声称逐卡事件已实现。不能把已结算的太空VP到下一回合再补发；普通单格奖励在该步骤批次结束时进入胜负服务。

## 6. 保存、异常与回放

一次普通尝试没有中途玩家选择，因此用一个事务提交卡牌、骰子记录、次数、轨道、奖励和结果；UI动画可以随后播放。若内部处理器错误，整个本次事务回滚，不留下“牌丢了但骰子没记”的状态。

同AttemptId/AdvanceId重试返回原结果；存档恢复不重新掷骰、不再发先到奖。不同命令不能复用已消耗卡牌或过期快照。回合末弃牌有PendingDecision时，保存Owner、LegalCardIds、DecisionId与继续位置；只向拥有者公开候选手牌，其他玩家只看到允许公开的行动结果。

~~~mermaid
flowchart TD
    A[验证太空用牌] --> B[消耗一次尝试并掷骰]
    B --> C{成功?}
    C -->|否| D[保留位置]
    C -->|是| E[推进与奖励批次]
    E --> F[刷新能力查询结果]
    D --> G[完成事务]
    F --> G
    G --> H[胜负检查与回合继续]
~~~

异常范围包括：缺失目标格、非法骰点、未知卡牌策略、跨版本数据、负尝试次数、损坏位置或不一致到达记录。全部明确失败，不以默认值继续。
