# 策略游戏工程参考与本项目取舍

description: 2026-10-15根据用户要求查阅一手工程资料；记录可采用的机制、适用边界和下一版可玩验收，不把他人架构直接等同本项目实现。

Factorio开发团队在2015年的技术日志中解释了锁步模拟与非确定性造成的不同步。借鉴其确定性约束：随机源、操作顺序和结果日志需可复现；本项目有隐藏手牌，仍采用权威宿主和按身份过滤快照，不复制文中当时的全量P2P方案。来源：https://www.factorio.com/blog/post/fff-76 。这是历史文章，不代表其2026实现全貌。

Unity官方Unity6命令模式教程将玩家动作表示为对象，便于组织、记录和调度。我们的SessionCommand/RuleEngine边界与此相符；命令本身不授予身份，仍需宿主验证版本、固定身份和幂等。同样不因教程带Undo就给正式牌局增加任意撤销：隐藏信息和随机结果已经揭示时必须有专门规则。来源：https://learn.unity.com/course/design-patterns/tutorial/use-the-command-pattern-for-flexible-and-extensible-game-systems 。

本项目取舍：Core纯C#、UI经IGameSession提交意图、地图只显示公开/显式观察状态、共享规则JSON统一数据。每批可玩验收覆盖正常路径、待选择恢复、错误反馈和重试；自动测试不能替代真实地图点击。现有command/state/data基础保留，不引入新框架或全工程重构。

下一批建议直接做头条试玩入口：真实发牌和现有部署后进入双边选头条；手牌明确显示可选/未实现/已锁定；另一方锁定前正常视图保密，单人观察入口单独标注；选齐后显示顺序、成功或取消、待选择方；完成接苏联第一行动，回合末后新回合再次进入头条。保留旧已验收Demo，独立构建HeadlinesPlaytest。

验收必须走完整小闭环：开局→双方锁定→头条结算/等待选择→普通出牌→回合末→下一回合头条。另设明确标注的fixture验证叛逃者，不把调好的手牌冒充正式随机开局。仍未实现的普通事件、特殊回合末和最终计分应提示边界，不自动跳过或篡改规则。

不以“设计文档齐全”或“测试数量增加”代表可玩完成。此文是工程方向记录，后续实施仍要读取具体模块与计划。
