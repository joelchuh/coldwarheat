# 项目知识工作流

仓库根目录相对于本文件为 ../../..。先阅读根目录 AGENTS.md 的当前阶段约定，再检查 Git 状态，保留已有修改。

1. 从根目录 Docs/Wiki/index.md 的 description 选择相关主题，不一次性加载全部 Wiki。
2. 读取对应知识点，确认实现状态、规则来源、代码符号、直接依赖和测试入口。设计文档不能证明代码已存在。
3. 使用 rg 定位符号，按需要读取函数、类型定义、调用方和测试。允许为正确理解而扩展上下文；小文件或跨文件不变量需要时可完整读取，不机械限制行数。
4. Wiki 与代码不一致时，以实际代码说明当前行为，并修复知识条目；规则正确性仍需经确认的规则资料判断，不凭代码或记忆决定。
5. 修改完成后更新受影响的知识点、流程和测试映射。在 Docs/Worklogs 中记录本次目的、改动、真实验证结果、限制和下一步。避免把工作日志复制成多份知识正文。
6. 遵循 Docs/Wiki/git-workflow.md 审阅、提交和同步。用户已授权本项目的日常 Git 提交与推送；同步失败保留本地历史并如实报告，不强制推送。

没有实现的规则、类或测试必须标记待实现，不生成虚假的符号链接或通过记录。规则设计阶段不因本技能而擅自实现游戏。
